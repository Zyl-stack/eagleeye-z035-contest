# 小目标检测与跟踪的场景回归

## 适用范围

适用于大画面中小球、小型运动目标和多人密集场景。先建立 PC 可复现基线，目标板性能另测。检测器负责候选，调度/持球权模块负责业务选择，保持职责可测试。

## 工作流

1. 合并数据前审计 class_id 重映射、图片/标签配对、bbox 范围、空标签、重复图片和 train/val/test 泄漏。两个数据源若分别只标球员或球，未标另一类不能自动当可靠负样本；抽样复核缺标并记录处理策略。
2. 记录数据版本、来源许可状态、类别框数、图像尺寸和小目标尺寸分布。按视频/场次分组划分；先审计再训练。
3. 用极小训练作业验证数据加载、保存、验证与导出链路；明确 smoke 指标不用于选最终模型。正式训练固定 seed/config/基座权重、数据清单及模型哈希。
4. 将测试分为成功小球、极小漏检、快速传球、遮挡恢复、多人交叉和假球干扰。保留标注视频、逐帧目标流及 metrics，以视频场景而非单张最佳图判定。
5. 分块推理时记录 tile 大小、overlap、坐标回映、跨块 NMS 和边界漏检。分别测完整帧耗时、召回与误检；分块提高可见性也可能显著降低吞吐。
6. PLAYER/BALL 分开匹配，门限由目标运动特征与真实 dt 决定。短时漏检保留同 ID、valid=0 和 miss_count，恢复后在约定窗口内再关联；过期后可分配新 ID，不承诺无限遮挡重识别。
7. 候选数受限时保留任务关键类别，测试 16 人以上场景下 BALL 是否被截掉。低置信候选不能自动等价于真实球；向下游保留置信度和有效性信息。
8. 用人工真值核对 ID switch、漏检持续时间和恢复行为。只要 tracker 产生了编号，不能称为“稳定身份跟踪已经验证”。

## 交付与通过条件

提供权重/config/hash、数据审计摘要、成功与失败案例、视频、候选流和时间元数据。关键场景达到本队预先定义的门限才通过；未定义阈值时先给结果，不事后挑一个有利阈值。

## 失效条件

用单帧复制视频证明动态跟踪、无真值声称 ID 稳定、使用不同 ONNX/输入尺寸复现旧指标、只保存被 Git 忽略的本机产物而不交接、用 PC 指标承诺板端 FPS，均不满足本流程。

## 已验证效果与失败来源

[E07](../evidence.md#e07小球回归需要保留失败案例)：CPU 小数据冒烟 mAP50=0.00063 与正式训练指标明确分开；真实 1080p 片段暴露小球漏检和低置信假球，分块检测提供可联调输出但仅 0.817 PC FPS。候选预算增加 BALL 保留策略。模型换任务、换输入分辨率和领域后需要重新评估。

## 可直接使用的提示词

> 用现有权重建立小目标视频回归，先审计数据和模型身份，再跑成功、漏检、遮挡、快速运动和假阳性用例。输出源坐标检测流、标注视频、采样时间与实测吞吐。检查候选上限是否丢关键类别，明确短时 ID 保持的有效窗口；按实际执行环境分别报告 PC 结果和板端待测项。
