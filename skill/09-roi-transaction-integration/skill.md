# 跨模块语义适配与 ROI 事务闭环

## 适用范围

适用于多个队员或多个进程协作的检测→ROI 请求→增强→精分类链路。先读已有接口与工程，尽量复用适配层，不因新模块接入随意改动冻结 ABI。

## 工作流

1. 给每字段写“产生者、含义、单位、范围、时钟/帧基准、消费者”，逐项对照。类别数字、区域枚举、置信度和速度即使同名也需语义核验。
2. 转换例：u8 confidence 到百分数采用约定舍入；Q8.8 速度除 256 后按约定舍入/饱和；空间区域由几何位置计算。不能把混合 OBSTACLE 类自动映为特定 BICYCLE/CONE，无法映射时显式拒绝或标 UNKNOWN 并记录。
3. 请求至少绑定 request_id、target_id、source_frame_id、requested ROI、deadline 和必要的模型/坐标版本。返回记录 applied ROI、图像来源与结果，匹配三个 ID 及有效期限再提交。
4. 明确 source_frame_id 是产生坐标的检测帧还是实际裁图帧。若预测未来 ROI，分别记录 reference_frame_id、capture_frame_id、预测 horizon/dt，不能用同一字段隐藏跨帧含义。
5. 固定大小 ROI 对左上角做 clamp，返回实际坐标。源图小于 ROI 时需明确 reject/pad 策略。全帧放大后裁 ROI 与 ROI-only 硬件计算的资源/带宽不同，报告实际路径。
6. 注入错误 request ID、错误 target/frame、重复结果、超时、乱序、目标消失和上一会话 ID 重用。正常结果一次提交，旧结果不改变当前焦点或风险。
7. 分层替换：先合成输入与软件增强跑闭环，再接真实视频，再替换实际 FPGA ROI 与模型。每一步保留同一字段与故障回归，不把软件闭环结果写成硬件闭环。
8. 交接当前版本、适配表、示例消息、运行入口和原始报告，使用 [assets/handoff.md](assets/handoff.md)。消息草稿由用户自行发送，技能本身不授权外发。

## 通过条件与失效条件

正确请求/结果能闭环且所有故障注入按约定拒绝或恢复；未定义 ID 生命周期、返回 ROI 无坐标依据、漏做类别语义映射、只展示风险变化而没证明增强图进入分类器时，不算完整验收。

## 已验证效果与失败来源

[E09](../evidence.md#e09字段同名不代表语义兼容)：旧检测与注意力的置信度、Q8.8、类别编号和区域语义不同；现存 12 帧软件报告记录正常结果接受、过期结果拒绝与唯一 request ID。该结果使用合成视频、Pillow 和 VOC 分类器，实机替换仍需重新验收。

## 可直接使用的提示词

> 先检查两侧现有接口，为每字段建语义/单位映射，再实现隔离适配层。将请求和结果绑定到 request、target、source/capture frame，返回 applied ROI；用正常、错误 ID、乱序、重复和超时数据测试。给出闭环证据、拒绝原因和软件/硬件输入边界，生成可直接交接的消息草稿。
