# 预处理张量的完整数值验收

## 适用范围

适用于图像转神经网络输入张量、替换 CPU resize 或实现 FPGA 预处理。输入规格必须来自实际运行模型的配置和代码。模型换版、letterbox 改为直接拉伸、RGB/BGR 变化时重新冻结契约。

## 工作流

1. 建表记录源尺寸、有效 stride、字节序、通道序、目标形状、dtype/endian、输出布局、resize 映射、clamp/padding、归一化常数、运算顺序和中间舍入。明确 stretch、letterbox 或 crop。
2. 独立 CPU 参考先用足够精度计算，按约定时刻转 FP32；硬件固定点或 ROM 路径另列误差预算。不能以复刻 RTL 索引的模型充当唯一参考。
3. 保存完整输入和完整输出。至少覆盖全零、全满、每色不同的非线性图案、四角/边缘脉冲和实际采集帧，以同时暴露通道、相位、边界与布局错误。
4. 逐值比较总数量、非有限数、bit exact 数量、最大绝对误差、RMSE 和首个超限位置。调用本目录 `scripts/compare_f32.py`；其输入是小端 raw FP32，位置按实际布局解释。
5. 验证 AXI-Lite AW/W 独立到达、忙时启动、复位恢复、各路独立背压、TLAST/TKEEP、三个平面全部完成。内存 NCHW 不要求三个平面按时间先后串行写入。
6. 比较替换前后的模型结果时，用同一原始帧、权重、阈值和 NMS；在源坐标系按类别/IoU 匹配框，报告新增、消失、坐标与分数变化。预处理数值通过不代表检测行为不变。
7. 分别记录核周期、流适配器周期、包含 cache/DMA/DDR 的端到端耗时。DDR 字节量只用于带宽预算，不能直接当测得时延。

## 示例与调用

本项目示例：640×360 RGB888 → 1×3×320×320，小端 FP32 NCHW。输入 691200 bytes，输出 1228800 bytes，每色平面 409600 bytes；最少 DDR 数据量 1920000 bytes/帧。

```sh
python scripts/compare_f32.py golden.f32 rtl.f32 --count 307200 --atol 0.000001
python scripts/compare_f32.py golden.f32 rtl.f32 --count 307200 --exact
```

默认 `rtol=0`；`--exact` 比较原始位模式，能区分 +0/-0。NaN/Inf 在普通和 exact 模式均拒绝。该工具不推断 tensor shape/通道语义，必须通过独立图案和规格检查。

## 失效条件

Golden 与实现共享同一错误、只比较少量值、改变 shape 后沿用旧相位/ROM、未检查 DMA 完成、检测比较换了模型或阈值，均不能形成验收结论。通用比例的 bilinear 不保证能使用本项目特定 1/32 网格 ROM。

## 已验证效果与失败来源

[E02](../evidence.md#e02预处理必须验证整个张量)：历史五类完整帧各 307200 值逐位一致。2024.2 的独立 IP 资源/时序报告已存在；2022.2、实际 DDR 延迟和模型框变化仍需验证。该经验来自 bicubic 与 bilinear 数学不等价、流 TLAST 与视频 TLAST 不同以及“核延迟”易被误写为系统延迟。

## 可直接使用的提示词

> 按模型的实际预处理代码建立 CPU Golden 与硬件验收。先冻结坐标映射、中间精度、颜色和张量布局；生成五类完整输入，逐值比较全部输出并定位首个差异。分别报告数值、流协议、核延迟、DDR 端到端和模型检测差异的证据状态。目标工具未运行时说明验证缺口。
