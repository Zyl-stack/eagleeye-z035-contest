# 持续采集下的 DDR 帧快照

## 适用范围

适用于相机生产帧、显示或推理消费者异步读取同一 DDR 环的系统。先从实际硬件导出确认 VDMA 方向、地址、帧槽、stride、缓存属性及帧完成语义。此流程不授权改动既有硬件。

## 工作流

1. 画出写者、读者和缓冲生命周期；辨明 MM2S/S2MM。记录每槽有效大小、分配跨度、总保留区、Linux 是否可能分配该内存、哪个进程/驱动初始化外设。
2. 从已证明完成的帧槽开始读，推理使用完整私有快照。慢推理默认取最新完成帧，避免无限累积历史帧；明确丢帧策略和 capture sequence。
3. 对复制期间不可覆盖给出可检验保证，优先使用写者交还所有权/租约、单调帧序号加完整性检查，或足够强的时间界限。仅“读前后环形指针相同”不能排除整环回绕。
4. 若依赖时间界限，测量最坏复制时间、调度停顿、生产最快帧周期和所选槽的剩余安全窗口，留裕量；超过界限时丢弃快照并重试。不能假定平均 memcpy 时间足以证明安全。
5. 描述 CPU cache 与 DMA 可见性：CPU 写输入后在适当平台 clean；DMA 写输出前处理可能脏的目的行，完成后 invalidate 再读。不要把陈旧 CPU cache 行 clean 回相机刚写过的 DDR。使用受支持驱动/API和实际映射属性核验，`volatile` 不能代替一致性协议。
6. 导出首帧 raw/PPM，确认长度、RGB/BGR、stride、撕裂和边缘。在慢消费者、CPU 高负载、跨环回绕、复位/超时场景持续测试。
7. 分别测 capture/copy、preprocess、inference、postprocess、total。HDMI 刷新率、采集率、推理率和结果年龄分别报告，不能统称 FPS。

## 案例参数与输出

本项目历史例子：640×360 RGB888，有效大小 691200 bytes，三槽间距 0xb0000；地址必须从本次硬件/设备树重新取得。示例记录字段：`capture_sequence`、`source_frame_id`、复制前后生产序号、重试次数、快照年龄和总时延。

## 失效条件

消费者无法证明槽所有权、真实 stride 不明、内存未保留、两个驱动同时配置同一 VDMA、cache 映射不明、缺实际 frame-done 含义时，不能声明“安全最新完整帧”。应先解决输入一致性再评价模型效果。

## 已验证效果与失败来源

[E05](../evidence.md#e05vdma-私有快照保护推理输入)：现有实现完成私有快照及 raw-frame QEMU 推理。真实 VDMA 并发覆盖、最坏复制时间和环回保护没有独立板端证据。本技能保留其设计目标，并明确指针回绕推理的不足，防止把前后检查当成无条件保证。

## 可直接使用的提示词

> 审查这条 VDMA→DDR→推理链路的帧所有权。标出生产者何时可能覆盖每个槽，给出复制期间安全性的可验证条件，检查全环回绕、cache、stride 和 Linux 内存保留。先证明导出的私有帧一致，再分项测量耗时；没有实板证据时列明待测风险。
