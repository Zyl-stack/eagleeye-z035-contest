# HLS 算子到 Zynq 系统的迁移审计

## 适用范围

适用于拿到学长/第三方 HLS 仓库、Intel FPGA 推理后端或多分支加速工程后迁移到 Zynq。不能把改 `set_part` 视为整个运行时已移植。

## 工作流

1. 按 commit 列出训练/导出仓库、优化器/fuser/kernel、HLS 算子、host 应用、内核驱动、板级 BD 与脚本。用代码和哈希比较分支，不依据 final/less_resource 等名字判断内容。
2. 从顶层函数和调用点还原支持的算子、激活、量化、通道对齐、padding/stride、tensor layout 和维度上限。把网络未覆盖层列为 CPU/其他后端路径。
3. 先核对芯片完整 part（封装/速度等级）、工具版别、器件文件与可用授权。用目标工具查询 part 并最小 `set_part` 预检，失败即标明未进入综合。
4. 对照接口协议和参数位宽：AXI-Lite、AXI master、Avalon 或平台私有接口分别迁移。物理基址从本次地址表取得，寄存器偏移从生成驱动/RTL取得，不复制旧平台硬编码值。
5. 为 host/kernel 建内存表：逻辑张量、打包布局、分配长度、对齐、物理地址宽度、cache 同步、所有权、启动/完成/超时。CMA 示例只证明示例 IP 的调用方式，不能代替本 IP 驱动。
6. 先用 CPU 独立数值参考验证 C 仿真，再验证 RTL，最后做板级读写与代表性层/网络精度。根据实际支持算子决定 fallback；融合或量化变化需数值回归。
7. 先保存 baseline 的 II、latency、DSP/BRAM/LUT 和时序，再改变并行因子、buffer 或流水。一次改变一个关键因素，检查依赖、访存瓶颈及资源；源码 UNROLL 数翻倍不能直接推出吞吐翻倍。
8. HLS IP 打包后仍需 BD/PS7 DDR/时钟复位/地址分配/中断/bitstream 与 Linux 驱动集成。只有整板实测才能评价 DDR 带宽、端到端速度与功耗。

## 失效条件

顶层只覆盖少数融合层却宣称完整网络硬件化、缺 PS 初始化、借用不相干寄存器表、未发现驱动源码却假定 CMA 可用、器件预检失败却填写资源报告，均应退回证据不足状态。

## 已验证效果与失败来源

[E10](../evidence.md#e10综合阻塞要定位在真实阶段)：本项目 final_compare 的 HLS 仅覆盖 1×1+depthwise 等特定融合路径；host/驱动仍有旧平台假设。Z100 实际尝试在 set_part 阻塞，无该次综合指标。安装文件、版别、器件与授权被分开确认，避免无效反复重装或改源码绕过环境错误。

## 可直接使用的提示词

> 审计这些仓库到目标 Zynq 的迁移工作。先按文件/commit 画清模型、运行时、HLS、驱动和 BD 的职责，再提取算子限制与内存/寄存器契约。运行器件最小预检，建立 CPU/C/RTL/板端数值证据，最后评估并行优化；报告器件预检、IP 综合与网络部署各阶段的实际结果。
