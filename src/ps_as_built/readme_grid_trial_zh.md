# 九宫格人数优先的 ROI 试验（v6 设计记录）

本文件保留 v6 策略背景。v7 的实时移动实现请以
`README_SMOOTH_TRIAL_ZH.md` 和 `README_BOARD_ZH.md` 为准；下面提到的
每次推理最多移动 48 像素和 v6 实板命令不适用于 v7。

v5 为验证 PS PicoDet 能控制硬件放大器，每次只选择最高分的一个人体框。
原来的九宫格逻辑存在于裸机/PC 串口链路的 `grid_attention.c`，因此没有
自动出现在 PetaLinux 人体检测程序里。v6 把这个策略接回了板端 PS。

## 选择规则

1. 从 PicoDet PERSON 结果中保留置信度不低于0.5、尺寸正常的人体框；
   重叠度超过0.55的重复框只计一次，最多统计16人。
2. 按人体框中心点落入640×360画面中的3×3格子，选人数最多的格子。
   同数时优先维持原格。无可信人体时保持上次 ROI。
3. 首次选格后至少保持3次推理更新；换格还要求新格比当前格至少多2人，
   或当前格已经无人。原裸机保持16帧，但它的输入频率更高；当前 PicoDet
   约1 FPS，故试验版按3次推理更新约3秒设置。这个值可根据现场再调。
4. 三列分别给出 ROI 起点 x=0/160/320，三行起点 y=0/90/180，ROI
   始终是320×180。坐标每次推理最多移动48像素，8像素内保持不变。

`GRID inference_sequence=... row=... col=... players=... switched=...`
每次推理都会出现。`FOVEA request=... mode=2` 表示当前 ROI 被硬件接收。
小目标框不会逐一显示，仍只显示一个青色 ROI 和现有 PL 放大画面。

实板先运行 `FOVEA_ROI=1 ITERATIONS=20 sh ./run_board.sh`，观察九宫格
选择是否符合画面人数分布。退出后可用 `./bin/fovea_ctl direct` 回到全局画面。

对两轮 v5 实板日志的离线回放：

- 20帧/93个输出框：首次选格外，发生1次实际换格；移动 ROI 提交8次。
- 20帧/194个输出框：首次选中心格后保持不变；移动 ROI 提交0次。

这是对**已有检测结果**的回放，不能代替 v6 真实板端观察。当前手机屏幕
没有占满 OV5640 画面，背景物体也可能被当成人；如果九宫格选偏，后续
应先限定足球视频有效区域，或调整拍摄位置。

VDMA 的 `0x15810` 错误位和严格的“最新完整帧”证明仍未解决，v6 不改
VDMA/RTL/设备树/BOOT.BIN/image.ub，也不会清除那些错误位。
