# EagleEye Vitis 2022.2 Shared Configuration

This directory contains the filtered Vitis/Eclipse project descriptions for
the C-side A/C bring-up. It is a shared configuration reference, not a copy
of a complete local Vitis workspace.

## Projects

- Platform: `eagleeye_platform_v2`
- System: `eagleeye_fovea_smoke_test_v2_system`
- Application: `eagleeye_fovea_smoke_test_v2`
- Processor: `ps7_cortexa9_0`
- Domain: `standalone_domain`
- Vitis version used for validation: `2022.2`

The Application is configured for the Fovea AXI-Lite base address generated by
the current BSP:

```text
XPAR_FOVEA_AXIL_CTRL_0_BASEADDR = 0x40000000
```

The address is hardware-generated data, not a replacement for checking the
team member's own `xparameters.h`.

## Source ownership

The Application sources are intentionally not duplicated here. The canonical
source files remain in the repository locations:

- `vitis_axi_smoke_test.c`
- `src/platform_io_vitis.c`
- `src/a_fovea_adapter.c`
- `include/platform_io_vitis.h`
- `include/a_fovea_adapter.h`
- `include/register_map.h`

The optional second-level dynamic test is `vitis_dynamic_fovea_smoke_test.c` at
the repository root. It is intentionally kept outside the filtered Vitis
workspace metadata so another team member can add it to the Application after
the fixed smoke test is working.

The three Application C files in the validated local workspace were compared
with the repository versions using SHA-256 and were identical. Do not create
a second long-lived copy under `vitis/`.

## Import and rebuild notes

Use Vitis 2022.2 and import the three project directories as Eclipse/Vitis
projects. After importing, check the following manually:

1. Reassociate `eagleeye_platform_v2` with the local `system_wrapper.xsa`
   generated by the matching Vivado design.
2. Rebuild the Platform so that its local BSP and `export/` directory are
   generated.
3. Reassociate the System and Application with that local Platform export.
4. Confirm the processor is `ps7_cortexa9_0` and the domain is
   `standalone_domain`.
5. Confirm the Application include path points to this repository's `include/`
   directory.
6. Check the local BSP `xparameters.h` for the real
   `XPAR_FOVEA_AXIL_CTRL_0_BASEADDR` macro before building.
7. Build the System/Application in Vitis. Do not copy BSP, ELF, or Debug
   output back into this repository.

The copied Vitis metadata still contains paths generated on the original
machine, including the original XSA, Platform export, workspace location, and
Application include path. Those paths are deliberately documented here and
must be repaired during import; they are not portable paths for another PC.

## Smoke-test intent

The current smoke test sends one request with:

```text
request_id = 1
source_frame_id = 1
target_id = 1
ROI = (160,90,320,180)
MODE = BILINEAR
```

Expected software-side UART text is:

```text
FOVEA REQUEST SENT
ROI=(160,90,320,180)
MODE=BILINEAR
WAITING FOR FRAME LATCH
REQUEST LATCHED
```

`REQUEST LATCHED` means that the request was accepted at a frame boundary. It
does not mean that image processing has completed.

For the next validation level, follow `A_C_BOARD_BRINGUP.md`. The dynamic
test runs five fixed target frames through the real C ROI smoother, adaptive
mode policy, A-side ROI adapter, and Vitis platform write path. It does not
use a camera or B detector and must not be described as hardware verified
until `REQUEST LATCHED` is observed on the board UART.
